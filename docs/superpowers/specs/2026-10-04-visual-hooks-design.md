# nu-japanese — Round A (foundations) + Round B1 (kana & kanji visual hooks)

## Context
Live single-file course (12 weeks, JLPT N5 target) generated by `src/build.py`
from `src/content_*.py`; localStorage only, no backend; push to `main` deploys
on Vercel. The user wants a calm, adult-first learning environment on the SAME
content — no game mechanics. Pain points they named: futile handwriting drills,
no quick quizzes, no flashcards, no course tips, and above all no visual
signifiers for the fundamentals. This plan covers the first two rounds; active
practice, daily review and calm-UI restructuring follow in later rounds.

### Analysis that drives it (measured 2026-10-04)
- Reading-first and linear. 61 exercise items, none with model answers or
  feedback; 17 mention writing, 5 are pure copy drills. 12 self-checks are
  yes/no prompts with nothing behind them. Review is outsourced to Anki/Renshuu.
- Visual: a kana cell is glyph + romaji; a kanji card is glyph + text.
- Defects that block every new feature: stars keyed by position
  (`renderVocab` key = keyBase + '-v' + i in `src/build.py`); "Vocab known"
  counts appendix stars against a weeks-only total; TTS speaks
  `日本人 / にほんじん` etc. (43 of 273 week rows); the W9 te-form rule table is
  stored as `vocab`; the kanji list is duplicated (`content_weeks.py` grids vs
  `content_appx.py` `_K1_50/_K51_100`, 15 gloss drifts).
- Keep: zero runtime deps, private, any static host.

## Decisions (from the user, in order)
1. Order: A foundations → B visual signifiers first; C active practice,
   D gentle daily review, E calm UI in later rounds.
2. Hooks: original text hooks for all 92 kana; simple SVG line drawings only for
   ~20 picture-origin kanji; structural visuals (grouping, look-alike pairs,
   dakuten transformation) everywhere. No copying of copyrighted hook sets.
3. Round-1 B scope: kana hooks + look-alikes; kanji pictures + parts.
   Deferred: particle colour code (needs hand markup of ~89 sentence spans;
   auto-detection rejected — は in はじめまして, に in にほん), word-type badges.
4. Interaction: tap = play sound + open a detail sheet (bottom sheet ≤820px,
   side panel above). Grid stays clean.
5. Tests: `tests/` + `package.json`, jsdom as DEV dependency only; shipped
   `index.html` stays zero-dependency; README → "no runtime dependencies".
6. Hook review in three batches, each on its own branch, reviewed on the Vercel
   preview before merge: hiragana (46) → katakana (46) → kanji (100).

Non-goals: streaks, points, leaderboards, timers, lives, notifications,
handwriting/stroke-order features.

## Approach (recommended: data-first extension of the existing build)
Rejected: hooks inline in the existing kana tuples (kana grids appear in weeks
AND appendix → second copy, same drift problem as the kanji lists); moving to a
JS framework/bundler (breaks zero-dep, YAGNI).

### Round A — foundations (one branch, one merge; visible changes: the fixes, and "Total vocab" 273 → ~431)
A1. **Split assets out of Python strings.** Move `CSS` and `JS` from
    `src/build.py` into `src/app.css` and `src/app.js`; `build.py` reads and
    inlines them. Gate: output `index.html` byte-identical to current
    (`06006ef6…`) before anything else changes.
A1 traps (from review): both strings are raw and start with a newline right
    after `r"""` (CSS line 37, JS line 561) — preserve it; read with
    `encoding='utf-8'`; replace placeholders in one pass so a comment in
    `app.css`/`app.js` mentioning `__JS__`/`__COURSE_JSON__` can't corrupt
    output; after the byte-identical gate, escape `</` in the JSON blob (SVG
    strings arrive in B1.3).
A2. **Stable item IDs.** Vocab ID = `v:` + jp + `|` + reading (the word, not the
    row). Kana ID = `k:` + glyph, kanji ID = `j:` + glyph. Computed in
    `build.py`, emitted on each row in `COURSE` JSON. Review measured: no jp has
    two readings; 21 duplicate IDs with different glosses are the same sense.
    `src/id_aliases.json` maps an old ID → new ID when a typo fix later changes
    a word (test: every alias target exists).
A3. **One-time progress migration (non-destructive).**
    - **Generate `src/legacy_keys.json` first**, before A5–A7 touch content:
      all 538 positional keys (273 week + 265 appendix) → new ID. Review
      measured the layout identical in every historical build (007f42b →
      35f3e69); the one changed row `w10-s2-v6` (`はんぶん / はん` → `はん`) maps
      to はん. Committed once, never regenerated.
    - Detect from the **raw parsed blob**: `!(loaded.schema >= 2)` (existing
      blobs have no `schema`; `undefined < 2` is false). Default `state` gets no
      schema, so `Object.assign` can't fake it.
    - Before migrating, copy the raw string to `jp_course_v1_bak`.
    - Write stars to a **new field `known`** (set of IDs); leave `knownVocab`
      untouched so a rollback build still works.
    - Merge rule: an ID is known if **any** of its old keys is `true`; `false`
      entries are dropped (today `toggleKnown` stores `false` on unstar).
      Covers 102 IDs fed by several old keys, incl. きく, よる, しんぶん, はたらく.
    - If parsing or migration throws: set `storageBroken`, disable `saveState()`
      for the session (today `loadState` swallows errors and the next
      `renderWeek`/`go()` save overwrites stored data).
    - New `toggleKnown` deletes on unstar and re-syncs every row with the same
      ID on the page (さかな appears twice in the index).
A4. **Counts.** Total = unique starrable vocab IDs (weeks + index); known =
    known IDs that exist. Visible change: "Total vocab" goes 273 → ~431
    (review measured 436 unique, minus the 5 W9 rule rows) — say so in the
    release note.
A5. **Single kanji source.** New `src/content_kanji.py` (100 records:
    glyph, meaning, readings, examples — the richer week-grid data is canonical).
    Week grids reference ranges; the appendix is built from the same list.
A6. **Speak text.** Each vocab row gets a speak string: explicit 4th tuple
    element if present, else derived. Rule: if the jp cell has ` / ` and one
    side is kana-only, speak the **kana side** (27 rows put kanji first:
    `日本人 / にほんじん`, all W10 days, counters — speaking the kanji side gives
    `〜人` → ひと/じん); strip `(な)`, `[noun]`, leading `〜`; rows with `…` or
    `〜` inside a list get explicit speak text. Fixture first, covering week
    rows AND the ~50 affected vocab-index rows (`、` lists, `きれい(な)`,
    `この〜、その〜、あの〜`, `いちがつ…じゅうにがつ`) + controls + near-misses
    (`ゼロ / 零` → ゼロ, `いい / よい` → いい, `ごぜん 7じ` unchanged).
A7. **W9 te-form rules** become a `table` section (no audio/star, not counted).
A8. **Tests + README.** `node --test` suite with jsdom; README build/test/deploy
    section updated; `npm test` run before every push.

### Round B1 — visual hooks
B1.1 **Data.** `src/content_glyphs.py`: per kana `{id, romaji, hook,
     looksLike:[ids], voiced:[ids], example:[jp, reading, en]}`. Coverage is
     **142 glyphs** (the grids include all 50 voiced forms): 92 base get hooks;
     voiced records carry romaji + a link to their base ("か + ゛"). Look-alike
     targets may lie outside the course (工, 力, 二) — rendered, not required to
     have a record. Look-alike
     pairs defined once as groups (シツ, ソン, クケタ, ぬめ, れわね, るろ, はほ,
     さちき, いり, こに, あお, ウワフ, ユコ, ナメ, エ工, カ力, ニ二, へヘ…), expanded
     symmetrically. Voiced forms from an explicit table (no codepoint
     arithmetic). Kanji records in `content_kanji.py` gain `hook`, optional
     `origin` (only when well-established; otherwise the sheet says
     "memory hook"), optional `parts:[[glyph, meaning]]`, optional `svg`.
B1.2 **Detail sheet** in `src/app.js`: one `openSheet(id)` used by kana cells
     and kanji cards. Tap still plays audio via existing `speak()`. Big glyph,
     romaji/readings, hook, look-alikes (tappable → open that glyph), voiced
     forms, example word with audio. **Non-modal**: no scrim, the grid stays
     tappable and the next tap updates the sheet (so playing sounds in a row
     isn't interrupted). `role="dialog"` without `aria-modal`, Esc / ✕ close,
     focus returns to the tapped cell. Kana cells and whole kanji cards become
     `<button>`s (today: plain `div`, and only the kanji glyph `.k` is
     clickable). The sheet respects "Hide readings" (romaji hidden until
     tapped). Bottom sheet ≤820px with safe-area padding, side panel above.
B1.3 **Kanji visuals.** ~20 pictographs (from 日 月 火 水 木 山 川 田 口 目 耳 手 足
     人 子 女 大 雨 魚 犬 力 車…) get a two-step SVG (picture → character) inline in
     the sheet. Compound kanji show parts only when the parts carry a meaning a
     beginner can use (休 = 人 + 木, 男 = 田 + 力, 時 = 日 + 寺…). Parts checked
     against KRADFILE (EDRDG, CC BY-SA 4.0 → attribution line in Resources).
B1.4 **Batches.** Branch per batch: (1) sheet + hiragana hooks, (2) katakana
     hooks, (3) kanji hooks + SVG + parts. User reviews each on the Vercel
     preview (or a printed list in chat) before merge.
